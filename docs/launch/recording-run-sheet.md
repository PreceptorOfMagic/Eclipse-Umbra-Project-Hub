# Website media recording run sheet

Keep the completed production notes and original captures outside the public repository. Record the date, operator, client/host versions, hardware, take filenames and any edits. Public captions should state only what the footage actually shows.

## Before capture

1. Confirm both hosts are available and identify the actual client and hosts being captured.
2. Use live sessions, with clean desktops and the established wallpapers. Save any desktop/window state that must be restored.
3. Plan the input sequence and framing. Check both panes visually; clear notifications and private information.
4. Preserve an unmodified capture master outside Git. Start and stop the capture with the shot when recording an uncut demonstration.

## Review each take

- Watch the whole take, including its opening and ending. Check for dropped/frozen panes, unintended menus, notifications and private details.
- Inspect pointer movement and text at native resolution and at the website's narrower display size.
- Confirm that each demonstrated action has a visible result on the intended live host. Media review is not a substitute for release/runtime validation.
- Retain accurate game/artwork credits, recording disclosure and a description of any edits.

## Finish

End the session using Quit game, verify hosts are free, stop owned capture processes and temporary tasks, and restore saved windows, icons and cursor settings.

Export delivery copies under the [media contract](media-spec.md), review the exported files, update their manifest hashes, and run the checks there. Check desktop and mobile page layouts and native playback before publishing.

The Halo shoot is complete: both co-op layouts and their trims were approved on 8 October 2026. See the [recording plan](recording-plan.md) and [delivery inventory](../../site/media/README.md) for the published selections. Keep all original recordings and audio outside Git.
