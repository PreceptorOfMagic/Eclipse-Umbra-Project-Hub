Open-source game streaming

Two PCs. One screen.

In Eclipse/Umbra, the Eclipse client composes two live Umbra host sessions into one split-screen couch co-op experience—so two people can play side by side on the same display, even when a game only provides online multiplayer. Each PC still runs its own game session, so licences, accounts and game networking remain game-specific.

Built on work shared by Moonlight’s founders and community, Sunshine creator @loki-47-6F-64 and LizardByte’s maintainers, then Mariotaku’s Moonlight TV, GuiDev1994’s Aurora and ClassicOldSong’s Apollo. Meet the people and projects behind it.

The headline feature

Couch co-op without asking the game.

Each PC renders its own game and sends its own live stream. The Eclipse client joins the two pictures, routes each assigned controller to its chosen Umbra host, and presents one split-screen experience on the shared display. Neither player is a spectator and neither host is reduced to a recording.

One experience, two codebases

Eclipse and Umbra have clear jobs.

The public hub stays unified while the software remains split where it should: Eclipse is the client people use; Umbra is the host software installed on the gaming PCs. Each repository keeps its own source and technical instructions; release artifacts will be published separately.

Client · fork lineage: Moonlight TV → Aurora

Eclipse client

The large-screen client and co-op composer, built around the Moonlight streaming core and a remote-, keyboard- and gamepad-friendly LVGL interface.

  • Co-op host selection, pane layout and input assignment
  • Decoder-gated resolution choices through 4K and separate frame-rate choices through 240 fps
  • Capability-gated H.264, HEVC, AV1 and HDR paths on compatible webOS hardware
  • Performance overlay, on-screen keyboard and virtual mouse
  • Single-host streaming remains part of the same client

Host · fork lineage: Sunshine → Apollo

Umbra host

The matching host fork for co-op. It retains Apollo’s self-hosted streaming foundation and virtual-display workflow while carrying the host-side behaviour Eclipse needs.

  • On-demand virtual display at the client-selected size and refresh rate, with lifecycle-aware cleanup
  • Browser configuration, PIN pairing and per-device permissions
  • Per-device display overrides, text clipboard sync and session hooks
  • Optional input-only access and client-requested HDR path
  • Runtime-probed NVIDIA, Intel, AMD and software encoders

Beyond the headline feature

Co-op sits on a complete streaming stack.

Eclipse still works as a conventional one-host client, while Umbra retains the self-hosted controls inherited from Apollo. Co-op adds a second live session without discarding the tools that make ordinary game streaming useful.

Eclipse · stream choices

Tune the session to the client.

Choose decoder-gated presets from 720p through 4K—including 3584×2016 “3.6K”—or use native and custom resolutions. Frame-rate presets run from 30 to 240 fps, with custom fractional rates where the active decoder allows them.

Automatic bitrate follows resolution and refresh rate until manual control is used. The selector spans 5–400 Mbps; current Moonlight protocol negotiation caps the resulting video allocation at 100 Mbps.

Eclipse · picture and control

Keep the useful controls in reach.

Compatible webOS hardware can expose H.264, HEVC, AV1 and HDR10 paths; current desktop previews expose H.264 and HEVC. The in-stream overlay reports the negotiated codec, resolution, frame rate, round-trip time, drops, bitrate and processing latency.

A full on-screen keyboard and opt-in gamepad virtual mouse remain available. Capability-aware forwarding can include touchpad, rumble, trigger rumble, accelerometer, gyro and RGB features when the controller, client and host support them. In co-op, relative mouse movement and the virtual mouse target Player 1, the primary left/top pane.

Umbra · display and access

Build the host around each paired device.

Umbra can create a Windows virtual display at the client-requested size and refresh rate, apply a device-specific display override and follow a client HDR request where the Windows, driver and display path support it. It removes the display when the application or session is terminated; a temporary disconnect can retain a resumable session instead.

Its browser interface covers configuration, application management and PIN pairing. Paired devices can receive granular viewing, launch, input, clipboard and command permissions rather than sharing one unrestricted profile.

Umbra · host plumbing

Use the encoder path that actually works.

Umbra probes NVIDIA NVENC, Intel Quick Sync, AMD AMF and software encoder paths at runtime and selects a viable option. It also retains text clipboard synchronisation, connection and disconnection hooks, input-only access and stereo, 5.1 or 7.1 low-delay audio configurations for ordinary single-host sessions. Co-op deliberately requests stereo from both hosts so Eclipse can mix them or play one selected source.

Codec, HDR, resolution and frame-rate availability still depends on the GPU, driver, Windows version, client and display; an implementation path is not a universal compatibility promise.

The shape of a session

Streaming stays live from end to end.

Co-op is not prerecorded playback and it is not remote viewing of a single shared desktop. Two hosts keep producing current game frames; the client composes them for one display and keeps input ownership explicit.
