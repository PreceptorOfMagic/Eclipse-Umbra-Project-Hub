What the viewer sees

Both panes move at once.

Two visually different viewpoints react independently. No diagnostic overlay, tiny text, camera movement, title card or edit that could hide duplicated footage.

How to record it

Cut from the continuous proof take.

Capture the real Eclipse client while two live Umbra hosts encode. Record player 1 alone, player 2 alone and at least five seconds of simultaneous input before choosing the loop.

Acceptance

Same edit, two web formats.

The WebM and MP4 must decode frame for frame, stay within the file budgets, contain no audio or private metadata and resolve to the same source interval and hashes.

Short feature loops

GIF energy without GIF weight.

These are designed like the short animated feature panels on a game store page. The web version should use muted, looping WebM/MP4 for quality and size; an animated GIF or WebP derivative is optional only where a platform cannot embed video.

Loop 01 · independent input

Each controller owns one host.

Record: player 1 acts while player 2 is still; reverse; finish with both moving. Keep both panes continuously visible.

Use: homepage co-op explanation, Reddit post and README media block.

Loop 02 · layouts

Side by side becomes stacked.

Record: open the real layout control, switch orientation, return to live play and briefly swap the primary host.

Use: feature gallery and setup explanation. Do not hide the transition with a cut.

Loop 03 · setup flow

Two hosts become one session.

Record: use public-safe host aliases, choose both hosts, select layout and assign each controller.

Use: quick start and walkthrough. Pairing codes, addresses and account names must never appear.

Loop 04 · single host

The normal streaming path remains.

Record: a short conventional Eclipse-to-Umbra session from the same release candidates.

Use: “beyond co-op” section. Keep it secondary so it does not obscure the project’s defining feature.

Recording method

Capture truth first. Cut beauty shots second.

This sequence keeps the footage useful as both promotion and evidence. It also prevents an attractive edit from accidentally concealing that a pane was stale, duplicated or prerecorded.

  1. 01

    Freeze and identify the builds.

    Use the exact Eclipse and two Umbra release candidates. Record full commits, versions and artifact SHA-256 values in the private run sheet before rolling.

  2. 02

    Clear rights and privacy.

    Use a game or demo whose promotional footage is permitted, disable unlicensed music and voice chat, prepare public-safe accounts/host aliases, obtain consent and remove notifications, codes, addresses and reflections.

  3. 03

    Prove both streams are live.

    Inspect the physical display. Record one uninterrupted take containing player 1 alone, player 2 alone, simultaneous action, a real layout switch and another simultaneous action. Never arm playback.

  4. 04

    Record the supporting shots.

    Capture the host picker, input assignment, both layout orientations, a normal one-host session and the physical room. Keep a clean master without burned-in product names.

  5. 05

    Preserve lineage while editing.

    Hash every accepted source, keep two verified backups and map each delivery interval or still frame to its source. Add editable titles, three readable creator-credit cards, captions and visual descriptions only after the proof cut is locked.

  6. 06

    Review before replacement.

    Check rights, privacy, accessibility, metadata, reduced-motion behaviour, signed-out playback and every file hash. Only accepted files replace these placeholders.
