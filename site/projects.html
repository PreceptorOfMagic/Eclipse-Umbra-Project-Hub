Why the boundary matters

The split is practical, not cosmetic.

The shared Eclipse/Umbra name unifies navigation and presentation. It does not erase where code came from or collapse different obligations into a vague “project licence”.

Licences stay traceable

Client, host and optional transport packages can ship the exact source offers, copyright statements and third-party notices they actually need.

Releases stay understandable

A client update does not imply a new host installer, and a host driver issue does not contaminate the client release history.

Issues reach the owner

Decode, composition and client input go to Eclipse; capture, encoding, service and virtual display go to Umbra; integration reports can be linked across both.

Shared contract

Same banner, same links, honest lineage.

The publishing contract requires every repository’s first screen to identify Eclipse/Umbra as one project, state that repository’s role, link the sibling application and hub, show preview/release status and lead to the full acknowledgements.
