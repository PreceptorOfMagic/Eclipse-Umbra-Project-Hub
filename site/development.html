Development

One feature set, coordinated across two repositories.

Eclipse owns the client, composition and input-routing work. Umbra owns the Windows host, capture and encoder work. Keeping those histories separate preserves their upstream structure; designing them together makes cross-vendor co-op possible.

Eclipse sourceUmbra source

Why a combined project

The change could not live entirely in Aurora or Apollo.

The goal was to make two independent hosts behave like one couch co-op display across as many systems and GPU combinations as practical. That required a client that can coordinate and compose two sessions and a host that can produce the stream contract the composition requires.

Eclipse responsibilities

Client coordination

  • Discover, pair and launch one or two hosts
  • Negotiate compatible co-op modes and capabilities
  • Compose side-by-side or stacked output
  • Assign controllers, keyboard and mouse ownership
  • Decode, present, measure and log the final session

Umbra responsibilities

Host and encoder control

  • Capture each independent Windows game session
  • Create and manage the requested virtual display
  • Select ordinary hardware or custom co-op encoding
  • Expose enough capability information for safe negotiation
  • Record host facts and session diagnostics for the client bundle
Ports are welcome.

The work was not submitted as an isolated Aurora or Apollo feature because the working design depends on coordinated client and host changes. Anyone may adapt the functionality for Aurora, Apollo, Moonlight, Sunshine or another compatible fork, subject to the relevant licences. Improvements that reduce the need for a paired fork are welcome.

Contribution paths

Pick the repository that owns the behaviour.

Keep reports reproducible and changes narrow. Cross-repository proposals should link the matching issue or pull request on both sides.

Useful bug reports

Logs turn a hardware combination into evidence.

Eclipse can collect the details that are otherwise lost when a problem only appears on someone else's television, driver or GPU pairing.

Information to include in a report
IncludeWhy it matters
Build and platformExact Eclipse and Umbra versions, OS/firmware, architecture and install format identify the code that ran.
Hardware pathCPU, memory, GPU and driver, displays, panel, decoder/encoder capabilities, controllers and network explain which branches were available.
ReproductionSay whether one-host streaming works, which two host vendors were used, the layout, Player 1, settings, game/app and exact steps.
Visible resultDescribe what each pane and each controller did. Screenshots or a short phone recording often reveal failures counters cannot.
Diagnostic bundleSession start, events, statistics, end totals, host log, crash frames and unclean-exit records show where the path diverged.
