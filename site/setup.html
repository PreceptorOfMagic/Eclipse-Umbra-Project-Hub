Quick start

Two hosts, one client, one shared display.

Eclipse/Umbra does not add multiplayer to a single-player game. Each Windows PC runs its own game session through the Umbra host; the Eclipse client joins the two live pictures and routes each assigned input to the right PC.

Before you begin

What the co-op setup needs.

Start with ordinary single-host streaming working on both PCs. Co-op should be the last layer you add, not the first thing you use to diagnose a host, encoder, firewall or controller problem.

01

Two Windows gaming PCs

Each PC needs the compatible Umbra host, its virtual-display driver and a supported hardware encoder path. The game must allow two independent sessions; accounts, licences and online/LAN support are game-specific.

02

One supported Eclipse client

Use the Eclipse client on the shared display. The project rig uses LG webOS; Windows preview builds are also exercised. The Linux path remains integration work rather than a consumer release.

03

A reachable network and inputs

The client must reach both hosts through their firewalls. Have the two controllers or other intended inputs connected before assigning them to a pane.

Setup sequence

Build it one verified layer at a time.

The order matters: configure both Umbra hosts, install the Eclipse client, pair and test each host alone, then start the combined session.

1. Prepare the Umbra host on each PC

  1. Install the reviewed Umbra release and its virtual-display driver on both gaming PCs when those packages become public.
  2. Open the host web interface, choose Applications, and create exactly one entry named Co-op Pane. Capitalisation, the space and the hyphen must match.
  3. Enable Virtual display. Leave the command and preparation fields empty unless that PC intentionally needs a portable launch command.
  4. In Display Device settings, set Resolution to Use resolution provided by the client (default) and Refresh rate to Use FPS value provided by the client (default) so each pane can request the correct geometry.
  5. Save the entry and confirm Co-op Pane appears in a normal Moonlight-compatible application list. Repeat independently on the second PC.

For Device configuration, choose Activate the display automatically (ensure_active) when games reliably choose the virtual display. Deactivate other displays and activate only the specified display (ensure_only_display) is more deterministic, but temporarily disables the host’s other displays during the session.

2. Install the Eclipse client

There is no reviewed public installer yet. Do not download packages offered elsewhere under these names. The current source paths are:

  • LG webOS build and manual installation for the tested TV path.
  • Windows preview requirements and source-build packaging.
  • Linux remains release-branch integration work and is not presented as a finished consumer path.

The Windows client requires Windows 10 version 1803 or newer and a physical GPU/driver with the required D3D11VA H.264 or HEVC decode profile. It fails closed instead of silently turning a hardware run into software decoding.

3. Pair and test each host separately

  1. Allow the Umbra host through Windows Firewall and place the machines on networks that can reach one another.
  2. Add the first host in Eclipse, enter the PIN in Umbra and wait for its application list to load.
  3. Open one ordinary desktop or game entry as a single-host stream. Confirm live picture, audio and the intended controller, then disconnect cleanly.
  4. Repeat the same pairing and ordinary-stream test with the second host. Fix a failed host before adding the co-op layer.
  5. Finally, launch Co-op Pane alone on each host and verify that its virtual display is created and captured correctly.

4. Start the Eclipse/Umbra co-op session

  1. In Settings → Co-op, choose whether the shared stereo output mixes both players or plays Player 1 or Player 2 only. Surround modes remain available for ordinary single-host sessions; co-op requests stereo from both hosts for its client-side mix.
  2. From the Eclipse server screen, choose Co-op.
  3. Select two different paired Umbra hosts. Do not select the same host twice.
  4. Choose side-by-side or stacked panes and decide which host occupies Player 1, the primary position: left in side-by-side mode or top in stacked mode.
  5. Review controller and—where enabled—keyboard and mouse ownership. Relative mouse movement and the gamepad virtual mouse target Player 1 in the current co-op build.
  6. Start the session and confirm that both panes remain live and each player controls only the intended host.

Fast fault isolation

Fix the failing layer first.

A combined session cannot repair a host that does not stream correctly on its own.

A host is missing

Confirm the Umbra service is running and allowed through Windows Firewall. If discovery is filtered by the network, use Eclipse’s manual-add control instead of editing preferences.

Co-op Pane is missing

Both hosts must expose exactly Co-op Pane. Similar names such as “Coop Pane” or “Co-op pane” do not match.

A pane is black or wrong

Open that host’s Co-op Pane as a regular stream. Verify that the virtual display exists, the game selected it and the host display policy is appropriate.

Resolution or refresh is wrong

Restore the host’s client-driven resolution and refresh settings to auto, then confirm its virtual-display driver supports the requested mode.

Input reaches the wrong PC

Return to the co-op picker and review assignment by paired-host identity. Do not rely on host order, IP address or a copied configuration file.

Advanced layout

The client PC can also supply one pane.

A Windows PC running Eclipse can also be one of the two Umbra hosts, but this is a preview path with extra display-hook and input limitations. The local game reads its controller directly; keyboard/mouse focus for the local virtual display is not automated yet. Start with two ordinary remote hosts unless this arrangement solves a specific room constraint.
